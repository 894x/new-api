# 按请求体大小选择上游 HTTP 协议

## 配置与回退

渠道 → 编辑 → 高级设置 → HTTP 协议选择「自动」，开启「大请求使用 HTTP/1.1」。初始阈值 1024 KiB 仅为实验起点，不是根据线上对照试验得出的最优值。

- 每个渠道独立开关，默认关闭；关闭后立即对**新请求**恢复原策略，不中断在途请求。
- 最终上游请求体的已知长度 **大于或等于**阈值时使用独立 HTTP/1.1 keep-alive 池。
- 小请求和未知长度请求继续使用原有自动协商及 HTTP/2 分片策略。自动协商不保证上游一定支持 HTTP/2。
- UI 单位 KiB，允许 1–1048576 的整数；API 存储字节数，开启时允许 1–1073741824。输入 token 数、缓存 token 数不等于请求体字节数。
- 强制 HTTP/1.1 时关闭该开关。不是把一个请求拆成多个请求，也不压缩或改写正文。

```json
{
  "http2_connection_shards": 6,
  "http1_large_body_enabled": true,
  "http1_large_body_threshold_bytes": 1048576
}
```

上述字段位于渠道的 `setting` JSON 中。没有新数据库列，不需要迁移。

## 传输保证及成本

选择器在发送前只检查 Body/ContentLength 元数据，不为测大小读取、复制或缓存请求体；不添加重试、失败降级、并发限制或客户限流。Go 原有传输重试及网关既有业务重试保持原样。两个底层池按代理和协议策略复用，不按阈值、请求大小或渠道 ID 新建池。不会修改已经使用过的 Transport/TLS 配置。

HTTP/1.1 可能增加 TCP/TLS 连接、文件描述符和上游连接数；不能保证加速，也无法突破上游接收能力或线路带宽。HTTP/2 分片数不是总连接数硬上限。上线前先确认文件描述符及上游连接配额，之后对一个渠道做可回滚对照，不要同时改变分片数和大小阈值。

## 诊断与统计口径

管理员请求详情新增「上游传输尝试」：最终 body 字节数、命中阈值、路由原因、选用策略、实际协议、连接复用、GetConn→GotConn、DNS/TCP/TLS、GotConn→WroteRequest、写完→首字节、状态及错误分类。最多保留 8 次尝试，不记录正文、URL、代理凭据或密钥。可选时间缺失显示 `—`，不假装为 0。

**取得连接后写入耗时仍包含本地正文读取、HTTP/2 调度和流控等待，不是纯线上传输速率。** DNS、TCP、TLS 是子阶段，不能与取得连接耗时简单相加；多次内部取连接/写入时保留计数与最新阶段值。

渠道性能页提供：

- 实时共享连接池/分片 TCP 连接数、按渠道活动请求数；活动请求持续到响应 EOF、Close、错误或上下文取消，包含 SSE 响应阶段。活动请求也可能处于取连接阶段，并不等于活动 HTTP/2 stream 数。
- 浏览器打开期间每 15 秒采样的实时曲线，最多保留 40 点；不持久保存 TCP 连接历史。TCP 连接数属于**进程共享池**，不能当成某一渠道独占连接数，也不是某一个上游源站的计数。多实例部署需查看相应实例，不应把跨实例采样当作单进程连续曲线。
- 日志重建的历史并发、总耗时、请求发送、上游等待、连接获取及取得连接后写入曲线与 P50/P95/P99。缺失样本不绘为零；空时间桶仍保留。
- 按渠道、实际协议、固定 body 大小段、分流原因和配置阈值分组，提供样本、错误、取消、超时及复用计数。取每条日志最后一个传输尝试，避免重复计入同一条日志里的旧尝试。渠道重试产生多条日志时是日志/尝试口径，不是去重后的客户请求数。

历史并发仅从扫描到的已结束日志重建，包含网关到请求结束的时间跨度；不包含仍在进行的请求，也不能和实时上游活动数直接等同。分位数为固定直方图上界估计；超过最大时间桶时使用该组观测最大值，避免把长尾截成 600 秒。截断时显示醒目提示，不把部分样本宣称全天统计。

历史查询仅管理员按需触发：最多 24 小时，500 行/页、50000 行或 32 MiB 日志内容、5 秒超时、每进程同时 1 个诊断扫描。分组最多 256 个普通组及一个溢出组。这个保护仅限制后台诊断扫描，**不限制客户业务请求**。不后台每秒扫描数据库。实际数据库开销仍需上线观察；分页上限不意味着 SQL 排序和索引扫描没有成本。

标准 `relay/channel.doRequest` 路径具有完整逐次诊断；通过相同客户端的其他 SDK 路径仍可按 ContentLength 分流，但未必提供渠道归属及请求详情数据。WebSocket/独立供应商客户端不在本次完整诊断覆盖范围。旧日志没有新增字段，无法回补协议/大小分组。

渠道保存审计增加 HTTP 协议、HTTP/2 分片、大请求开关及字节阈值的 before/after 白名单，未提交 setting 的更新不会伪造传输配置变化。

## 本地验证及上线验收

自动测试覆盖 TLS 真实协商、阈值边界、未知/空正文、原样传输、HTTP/1.1 复用、CONNECT 代理、池复用、关闭开关、错误不跨协议重试、SSE 关闭/取消、跨桶并发、日志缺失值、长尾、配置校验、表单存取及审计脱敏。

建议上线后先只开启目标渠道，保持原分片数，以匹配时段、body 大小段、实际协议、样本量比较写入 P95/P99、连接获取 P95、失败/超时率及连接/FD/CPU。如果变差，关闭开关即可恢复新请求原策略。上线、灰度及真实负载收益验证需要单独执行；本次实现不部署线上。
